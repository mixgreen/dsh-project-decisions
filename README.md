# 项目决议 · Project decisions

[English](<README.en.md>) · [更新日志](<CHANGELOG.md>) · [贡献指南](<CONTRIBUTING.md>) · [版本与发布](<RELEASING.md>)

一个 DSH 原生插件：把项目中的**待定事项**与**已确认共识**放在两列中，让你和 agent 围绕同一份本地 Markdown 讨论。

**决议属于项目，不属于某次聊天，也不是全局任务看板。** 同项目的会话共享决议，切换项目则读取另一份文档。「已确认」表示达成共识，不表示代码已实现。

```text
项目会话：对话 | 轨迹 | 项目决议

当前项目 · 项目决议                 ＋新增事项

待定事项                           已确认共识
问题、背景、候选方案                已确认的结论与依据
[编辑] [确认共识 →]                 [编辑] [← 重新讨论]
```

## 功能

- **你发起**：只有用户通过面板新增条目，不自动生成示例或决议。
- **共同维护**：用户与 agent 可以编辑已有条目、确认共识、重新讨论。
- **项目共享**：会话只是入口；页面自动绑定所属 DSH 工作区，没有跨项目选择器。
- **本地优先**：每个工作区一份 `PROJECT_DECISIONS.md`，没有额外数据库。
- **上下文同步**：两列都提供给该项目的 agent，状态含义明确，不自动启动执行。
- **避免误覆盖**：保存检查内容版本，冲突时保留编辑草稿。

## 环境与兼容性

- 目标 DSH API：**0.2.2-rc.2**。包声明范围为 `>=0.2.2-rc.2 <0.3.0`，不代表范围内每个版本均已实测。
- 本机工作区；当前实现不开放共享访问的写入入口。
- 开发／打包要求 **Node.js 22+、npm、Git 和 tar**；CI 在 Linux 的 Node.js 22、24 上运行。
- 无第三方运行时依赖，无构建步骤。React 由 DSH 提供。

## 安装

本项目采用 **GitHub Release 的 npm 格式 `.tgz` 安装包**分发，不需要 npm 账号。包内保留 `@local/dsh-project-decisions` 名称，以兼容已有本地安装；`private: true` 仅防止误执行 `npm publish`，不妨碍打包安装。

### 从发布包安装

1. 在本仓库的 GitHub **Releases** 页面下载对应版本的 `.tgz` 和 `SHA256SUMS`。若还没有 Release，使用下面的源码安装方式。
2. 在下载目录校验：macOS 用 `shasum -a 256 -c SHA256SUMS`；Linux 用 `sha256sum -c SHA256SUMS`。
3. 在 DSH 的 **插件 → 添加插件** 中安装本地 `.tgz` 的绝对路径。若当前 DSH 版本的界面只支持目录，可先解压，再选择解压后的 `package` 目录。
4. 启用「项目决议」。重新加载界面；桌面端若仍使用旧的前端加载信息，保存输入、等待任务结束后完全退出再启动。

如果让 agent 安装：明确提供下载包的绝对路径，让它通过 DSH 插件管理器安装；不要手动修改 DSH profile 配置。

### 从源码安装／开发

克隆或下载本仓库后：

```sh
npm ci --ignore-scripts
npm run verify
```

然后通过 DSH 插件管理器安装当前源码目录。目录安装通常是链接模式；**不要删除或移动这个目录**。普通用户建议使用 Release 包，避免开发中的改动影响运行实例。

## 使用

1. 打开项目中的任一会话，在与「对话／轨迹」同排的标签中选择 **项目决议**；空间不足时在更多视图菜单中查找。
2. 确认页头的项目名称和文档位置。
3. 点击「新增事项」，填写标题和 Markdown 正文。第一次保存才创建文档。
4. 与 agent 讨论并补充已有事项，再用「确认共识」移到右列；需要重新讨论时移回左列。
5. agent 改动后，重新打开面板、重新聚焦窗口或点击「刷新」查看最新内容。

新增权限的边界：插件不提供 agent 新增工具，但拥有任意 shell／文件写权限的 agent 理论上仍能直接改文件。这不是操作系统级身份隔离。

## 数据与隐私

文档保存在**项目工作区根目录**，不是插件安装目录或全局配置目录：

```markdown
# 项目决议

## 待定事项

### [d-unique-id] 需要讨论的问题

背景、方案、补充信息。

## 已确认共识
```

- 条目 ID 保持稳定。分区标题和 `### [d-ID] 标题` 是保留语法；正文需要展示这些标记时放入闭合代码块。
- 临时 `cd` 到子目录不会另建决议文件；独立注册的 worktree 工作区有独立文档。
- 可以用外部编辑器修改符合格式的文档。未知格式或符号链接会报告错误，不覆盖原文。
- 文件保存使用版本散列与原子替换，但不承诺外部编辑器和插件之间的跨进程事务。
- 本插件本身不调用外部网络；**注入的决议会作为会话上下文发送给你选择的模型服务，并记录在 DSH 会话日志中**。不要把密钥或不适合交给模型的内容写入决议。
- 本插件源码仓库默认忽略自己运行时生成的决议文件，发布包也不会包含它。其他项目是否把决议纳入 Git，由项目维护者决定。

## Agent 工具

| 工具 | 行为 |
|---|---|
| `prd_read()` | 返回 `{ path, version, exists, rows }` |
| `prd_update({ id, version, title?, body?, status? })` | 修改已有条目，不创建、不删除 |

`rows` 为 `[id, title, body, status]` 的列表，状态为 `pending` 或 `confirmed`。agent 写入遵守计划模式和当前文件权限。快照按项目区分，最新版替代旧版；删除或损坏的文档会明确标记不可用。

## 升级与回退

1. 阅读目标版本的 [更新日志](<CHANGELOG.md>)，备份项目决议文档。
2. 下载并校验新包，在 DSH 插件管理器中安装；**包名保持不变，不需要先删除项目数据**。
3. 依据 DSH 返回的提示重启。只刷新浏览器不能保证 Host 代码已替换。
4. 打开同一项目，核对条目与状态。需要回退时安装上一版本的 Release 包，再重启验证。

当前版本没有数据迁移步骤。停用或卸载插件不删除决议文档。未来若改变文件格式，发布说明必须提供迁移和回退步骤。

## 已知边界

- 正文显示和编辑 Markdown 源文，不是富文本渲染器。
- 没有删除、归档、拖拽排序或任务执行追踪。
- 面板不实时轮询；页面内导航保留草稿，整个页面刷新／重启会丢失未保存草稿。
- 部分第三方 UI 插件可能隐藏会话视图导航。
- 当前主要界面支持中英文，部分错误详情仍为中文。

## 维护与发布

```sh
npm run verify                  # 语法、测试、版本/更新日志一致性
npm run release:pack            # 检查并生成 dist/ 安装包、校验值和发布说明
npm run release:prepare -- patch # 工作区干净且 Unreleased 有条目时准备下一个版本
```

完整流程见 [RELEASING.md](<RELEASING.md>)。发布命令不会自动提交、打标签或推送。将 `vX.Y.Z` 标签推送到 GitHub 才会触发 Release 工作流，使用该版本更新日志生成发布说明。
