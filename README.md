# 项目决议 · DSH 插件

一个人发起、人与 agent 共同维护的项目决议板。**待定事项 → 已确认共识**，不是执行任务看板。

## 使用

1. 在 DSH 插件管理器添加本地目录，启用「项目决议」。
2. 打开项目中的任一会话，在「聊天／轨迹」同排的视图标签中选择「项目决议」（空间不足时在更多视图菜单内）。决议板直接绑定该会话所属项目，不提供全局入口或跨项目选择器。
3. 你点击「新增事项」，输入标题和 Markdown 正文。首次新增才创建文档。
4. 你或 agent 补充条目，点击「确认共识」移到右侧；「重新讨论」移回左侧。
5. 两列都会提供给该项目的 agent。注入不会主动唤醒 agent，也不代表授权执行任何任务。

没有项目条目时不会自动生成示例或决议。正文以保留换行的 Markdown 源文显示和编辑，第一版不提供富文本渲染或拖拽排序。

面板重开、窗口重新获得焦点或点击「刷新」时重读文件。编辑草稿按项目保留在当前页面内存中，切到对话再回来不会丢失；刷新整个浏览器页面或重启会清空未保存草稿。打开面板期间不实时轮询 agent 的修改。

## 本地数据

会话只是打开入口，决议仍属于项目：同一项目的多个会话读取和修改同一份文档，切换到其他项目的会话则显示另一份文档。页头始终显示所属项目名称与文件位置。未关联工作区的会话会提示先从项目工作区打开，不会回退到上次项目。

每个已注册 DSH 工作区根目录只有一份 `PROJECT_DECISIONS.md`，无数据库副本。临时切换会话工作目录不会改变它的所属项目。独立 worktree 工作区不自动同步。插件停用或卸载不会删除文档。

```markdown
# 项目决议

## 待定事项

### [d-unique-id] 待讨论标题

背景、候选方案与补充信息。

## 已确认共识
```

条目 ID 保持不变。两个二级分区与 `### [d-ID] 标题` 是保留语法；正文如果需要展示这些标记，请使用闭合代码块。可用外部编辑器维护此格式，之后在面板点「刷新」。未知格式或符号链接会报告错误，不覆盖文件。

保存使用内容散列进行并发检查，并以临时文件原子替换。两个插件调用不会静默互相覆盖；外部编辑器与最终原子替换之间仍有极短的竞争窗口，不承诺跨进程事务。发生冲突时保留编辑草稿，刷新比较最新条目后，明确选择使用最新版本再保存。

## Agent 工具与权限

- `prd_read()`：返回 `{ path, version, exists, rows }`。
- `prd_update({ id, version, title?, body?, status? })`：只修改已有条目，无创建、删除或 upsert。
- `rows` 每行固定为 `[id, title, body, status]`，status 为 `pending` 或 `confirmed`。
- agent 写入受当前计划模式和文件权限限制；UI 是用户自己的编辑入口。
- 只有用户在 UI 中新增。具备任意 shell／文件权限的 agent 理论上仍能直接改 Markdown；插件不能提供操作系统级的身份隔离。上下文明确要求不绕过此限制。

初次加载、恢复、内容改变后提供完整快照。文件变化由界面写入或后续 agent 步骤观察；不轮询。相同 live agent 的相同版本不重复发送。快照纳入 DSH 会话日志，后续完整快照替代同项目旧快照的语义。文件删除或损坏会明确告知 agent 旧内容不可继续视为最新。

此插件仅支持本机工作区。UI API 使用 DSH 已认证的 owner-only Connection Fetch 路由，不开放远程共享访问。

## 开发

无需第三方依赖或构建步骤。`client.js` 是 DSH 浏览器模块工厂，不是独立网页。

```sh
npm test
npm run check
```

文件分工：`store.js` 处理 Markdown 与版本化保存；`host.js` 处理工作区、工具、权限和上下文；`client.js` 处理两列面板。安装通过 DSH 插件管理器，不修改 profile 配置或应用安装目录。

当前目标 API：DSH 0.2.2-rc.2。升级已加载的 Host 代码后可能需要重启 DSH；不要依赖浏览器刷新重载 Host 模块。
